# Audit Fix Prompt

You have the output of `kazam audit` at `scripts/audit-results.json`.

## Configuration

Before starting, confirm with the user:

1. **PR strategy** - how to group fixes into pull requests:
   - `single` - one PR with all fixes (fast, simple review)
   - `per-owner` - one PR per owner (each owner reviews only their pages)
   - `per-page` - one PR per page (granular, easy to revert)

2. **Fix scope** - which issue types to fix:
   - `all` - fix everything the agent can (default)
   - Pick from: `overdue`, `due_soon`, `missing_owner`, `no_sources_of_truth`, `empty_content`
   - `expired` pages should be flagged for archive, not refreshed

3. **Notification** - how to notify owners:
   - `messaging` - DM owners via Slack or Teams MCP (whichever is available)
   - `pr-review` - request PR review from owners on GitHub
   - `both` - message + PR review request
   - `none` - just open the PRs silently

## What the agent can fix automatically

| Issue | Auto-fix |
|---|---|
| `overdue` / `due_soon` | Bump `freshness.updated` to today if content is confirmed current |
| `missing_owner` | Look up likely owner from git blame / commit history, set `freshness.owner` |
| `no_sources_of_truth` | Use the sources-map wish pattern: scan repos, map files to page, add entries |
| `empty_content` | Flag for human - can't generate content without context |
| `expired` | Flag for archive review - run `kazam freshness act <path> archive` if owner confirms |

## Workflow

1. Read `scripts/audit-results.json`
2. Group issues by the chosen PR strategy
3. For each group:
   a. Create a branch (`audit/fix-<group-name>`)
   b. Apply fixes to the YAML files
   c. Commit with a descriptive message
   d. Open a PR with the issues addressed listed in the body
4. Notify owners per the chosen notification strategy
5. Report summary: PRs opened, issues fixed, issues flagged for human review

## PR body format

```markdown
## Audit fixes - [group description]

**Issues addressed:**
- [x] `overdue` - path/to/page.yaml (bumped freshness date)
- [x] `missing_owner` - path/to/other.yaml (set owner to user@company.com from git blame)
- [ ] `expired` - path/to/old.yaml (flagged for archive - needs owner confirmation)

**Health score impact:** 85% → 92%

Generated by `kazam audit` + audit-fix wish
```

## Important

- Never auto-archive expired pages - always flag for owner review
- For `overdue` pages: only bump the date if the content still matches the sources_of_truth. If sources have drifted, flag for content review instead of just bumping the date.
- Use `sources_of_truth` URLs from the audit JSON to check drift before bumping dates
- For `missing_owner`: prefer git blame on the YAML file, then fall back to the `owner` field on sibling pages in the same directory
